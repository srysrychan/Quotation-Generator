# Feature Specification: 報價單匯出工具

**Feature Branch**: `001-quotation-export-tool`  
**Created**: 2025-10-15  
**Status**: Draft  
**Input**: User description: "Quote-web 報價單匯出工具｜功能規格定義"

## 功能概述

本功能為個人創作者、SOHO 接案者與中小型企業業務提供一套離線型報價單建立與匯出工具。使用者可以快速建立單次報價單、編輯客戶資料與報價項目、即時儲存於瀏覽器本地、並匯出為 PDF 或 CSV 格式。匯出完成後，系統自動清除所有資料，確保無歷史紀錄殘留，符合一次性報價需求。

**目標使用者**：
- 個人創作者（設計師、攝影師、顧問）
- SOHO 接案者
- 中小型企業業務人員
- 需要快速產出專業報價單但不需要複雜系統的使用者

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立並編輯報價單內容 (Priority: P1)

業務人員小陳需要為客戶快速建立一份報價單。他開啟網頁工具，輸入客戶名稱「ABC 公司」、聯絡人 Email 與電話，然後新增三個報價項目：「網站設計」、「LOGO 設計」與「名片設計」，分別輸入數量與單價。系統自動計算每個項目的小計與總金額。小陳在備註欄位補充付款條件與交付時程。

**Why this priority**: 這是核心功能，沒有編輯能力就無法建立報價單。這是 MVP 的基礎，必須優先實作。

**Independent Test**: 可以透過開啟網頁、輸入客戶資料、新增至少一個報價項目、確認小計自動計算來獨立測試。即使沒有匯出功能，使用者仍可看到完整的報價單內容。

**Acceptance Scenarios**:

1. **Given** 使用者開啟空白報價單頁面，**When** 輸入客戶名稱「測試公司」、Email「test@example.com」與電話「0912345678」，**Then** 系統顯示已輸入的客戶資訊
2. **Given** 報價單已有客戶資訊，**When** 點擊「新增項目」並輸入品項「網站設計」、數量「1」、單價「50000」，**Then** 系統自動計算小計為「50000」並顯示於表格中
3. **Given** 報價單已有一個項目，**When** 再新增第二個項目「LOGO 設計」、數量「2」、單價「8000」，**Then** 系統顯示兩個項目，總金額自動更新為「66000」
4. **Given** 報價單已有多個項目，**When** 修改第一個項目的數量從「1」改為「2」，**Then** 該項目小計自動更新為「100000」，總金額更新為「116000」
5. **Given** 報價單已有多個項目，**When** 點擊刪除第二個項目，**Then** 該項目從列表中移除，總金額自動重新計算

### User Story 2 - 匯出 PDF 格式報價單 (Priority: P1)

小陳完成報價單編輯後，需要將報價單以 PDF 格式傳送給客戶。他點擊「匯出 PDF」按鈕，系統產生一份套用專業樣式的 PDF 檔案（包含公司 LOGO、報價單標題、客戶資訊、項目表格與備註），檔案自動下載至電腦。匯出完成後，網頁自動清空所有內容，回到空白狀態，準備建立下一份報價單。

**Why this priority**: PDF 是最常用的報價單格式，客戶期待收到專業且可列印的文件。這是使用者完成工作流程的關鍵步驟。

**Independent Test**: 可以透過建立一份包含客戶資訊與至少一個項目的報價單、點擊「匯出 PDF」、確認 PDF 檔案下載成功、開啟 PDF 確認內容正確、確認網頁內容已清空來獨立測試。

**Acceptance Scenarios**:

1. **Given** 報價單已填寫客戶資訊與至少一個項目，**When** 點擊「匯出 PDF」按鈕，**Then** 系統產生 PDF 檔案並自動下載，檔名包含日期時間戳（例如：quotation_20251015_143022.pdf）
2. **Given** PDF 檔案已下載，**When** 開啟 PDF 檔案，**Then** 檔案內容包含完整的客戶資訊、所有報價項目、小計、總金額與備註，且中文字型顯示正常無亂碼
3. **Given** PDF 匯出成功，**When** 回到網頁，**Then** 所有輸入欄位已清空，顯示空白報價單狀態
4. **Given** 報價單已填寫內容但尚未匯出，**When** 重新整理頁面，**Then** 先前輸入的內容仍然保留（因為儲存於 localStorage）

---

### User Story 3 - 匯出 CSV 格式報價單 (Priority: P2)

小陳需要將報價單資料匯入公司的會計系統進行後續處理。他點擊「匯出 CSV」按鈕，系統產生一份包含所有報價項目的 CSV 檔案，檔案自動下載至電腦。匯出完成後，網頁自動清空所有內容。

**Why this priority**: CSV 格式方便資料再利用與系統整合，但優先度低於 PDF，因為大多數客戶期待收到 PDF 格式。

**Independent Test**: 可以透過建立一份報價單、點擊「匯出 CSV」、確認 CSV 檔案下載成功、使用 Excel 或文字編輯器開啟 CSV 確認資料正確、確認網頁內容已清空來獨立測試。

**Acceptance Scenarios**:

1. **Given** 報價單已填寫客戶資訊與至少一個項目，**When** 點擊「匯出 CSV」按鈕，**Then** 系統產生 CSV 檔案並自動下載，檔名包含日期時間戳（例如：quotation_20251015_143022.csv）
2. **Given** CSV 檔案已下載，**When** 使用 Excel 開啟 CSV 檔案，**Then** 檔案包含欄位標題（品項名稱、數量、單價、小計）與所有報價項目資料，中文字元顯示正常
3. **Given** CSV 匯出成功，**When** 回到網頁，**Then** 所有輸入欄位已清空，顯示空白報價單狀態

---

### User Story 4 - 響應式操作體驗 (Priority: P3)

業務人員小陳在外拜訪客戶時，使用手機開啟報價單工具快速建立報價單。他可以順暢地在手機螢幕上輸入客戶資訊、新增項目、查看總金額，並直接匯出 PDF 傳送給客戶。

**Why this priority**: 行動裝置支援提升使用彈性，但核心功能在桌面環境已可運作，因此優先度較低。

**Independent Test**: 可以透過使用手機或平板開啟網頁、完成報價單建立與匯出流程、確認所有操作順暢且介面元素適當調整來獨立測試。

**Acceptance Scenarios**:

1. **Given** 使用者使用手機開啟報價單工具，**When** 瀏覽頁面，**Then** 所有輸入欄位、按鈕與表格適當調整尺寸，可輕鬆點擊與輸入
2. **Given** 使用者使用平板開啟報價單工具，**When** 新增多個報價項目，**Then** 表格內容可橫向捲動查看，不會超出螢幕範圍
3. **Given** 使用者使用手機完成報價單編輯，**When** 點擊「匯出 PDF」，**Then** PDF 檔案成功下載至手機，可使用手機內建 PDF 閱讀器開啟

---

### Edge Cases

- **空白報價單匯出**：使用者未輸入任何內容就點擊匯出按鈕時，系統應顯示錯誤訊息「請至少新增一個報價項目」，並阻止匯出
- **數量或單價為零或負數**：使用者輸入數量「0」或單價「-100」時，系統應顯示驗證錯誤訊息「數量與單價必須大於零」
- **匯出失敗處理**：當 PDF 或 CSV 匯出過程發生錯誤（例如瀏覽器阻擋下載），系統應保留 localStorage 資料不清除，並顯示錯誤訊息「匯出失敗，請重試」
- **localStorage 資料損毀**：當 localStorage 資料格式異常或無法解析時，系統應自動重設為空白狀態，並顯示提示訊息「資料格式異常，已重設為空白報價單」
- **超長文字輸入**：使用者在品項名稱或備註欄位輸入超長文字（例如 1000 字）時，系統應正常儲存與顯示，PDF 匯出時應適當換行避免內容被截斷
- **瀏覽器關閉後重新開啟**：使用者編輯報價單到一半關閉瀏覽器，重新開啟時應自動載入先前未匯出的內容（從 localStorage 還原）
- **多個瀏覽器分頁**：使用者同時開啟多個報價單工具分頁，每個分頁的 localStorage 操作應獨立，避免資料互相覆蓋

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須提供客戶資訊輸入欄位，包含客戶名稱、Email、電話與備註
- **FR-002**: 系統必須提供報價項目表格，支援新增、編輯與刪除項目
- **FR-003**: 每個報價項目必須包含品項名稱、數量、單價與自動計算的小計欄位
- **FR-004**: 系統必須自動計算所有項目的總金額，並即時更新顯示
- **FR-005**: 系統必須在使用者每次輸入變更時，自動將報價單資料儲存至瀏覽器 localStorage
- **FR-006**: 系統必須在頁面載入時，自動從 localStorage 還原先前未匯出的報價單內容
- **FR-007**: 系統必須提供「匯出 PDF」功能，產生包含完整報價單內容的 PDF 檔案
- **FR-008**: PDF 檔案必須套用專業樣式，包含公司資訊、LOGO、報價單標題、項目表格與備註區
- **FR-009**: PDF 檔案必須支援正體中文字型顯示，避免亂碼
- **FR-010**: 系統必須提供「匯出 CSV」功能，產生包含所有報價項目的 CSV 檔案
- **FR-011**: CSV 檔案必須包含欄位標題（品項名稱、數量、單價、小計）與所有項目資料
- **FR-012**: 系統必須在 PDF 或 CSV 匯出成功後，立即清除 localStorage 資料
- **FR-013**: 系統必須在匯出成功後，將所有輸入欄位重設為空白狀態
- **FR-014**: 系統必須在匯出失敗時，保留 localStorage 資料不清除，並顯示錯誤訊息
- **FR-015**: 系統必須驗證數量與單價欄位，確保輸入值大於零
- **FR-016**: 系統必須在使用者嘗試匯出空白報價單時，顯示錯誤訊息並阻止匯出
- **FR-017**: 系統必須在 localStorage 資料格式異常時，自動重設為空白狀態並顯示提示訊息
- **FR-018**: 系統必須支援響應式設計，在手機、平板與桌面裝置上皆能正常操作
- **FR-019**: 所有使用者介面文字、標籤、訊息與錯誤提示必須使用正體中文呈現
- **FR-020**: 匯出的檔案名稱必須包含日期時間戳，格式為 `quotation_YYYYMMDD_HHMMSS.pdf` 或 `.csv`

### Key Entities

- **報價單 (Quotation)**: 代表一份完整的報價文件，包含客戶資訊、報價項目列表、備註與建立時間。關鍵屬性：客戶名稱、Email、電話、項目列表、備註、建立時間戳
- **報價項目 (Quotation Item)**: 代表報價單中的單一項目，包含品項描述、數量、單價與自動計算的小計。關鍵屬性：品項名稱、數量、單價、小計金額
- **客戶資訊 (Customer Info)**: 代表報價單的收件對象資訊。關鍵屬性：客戶名稱、Email、電話

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者可在 3 分鐘內完成一份包含客戶資訊與至少 3 個報價項目的報價單建立與匯出
- **SC-002**: 匯出的 PDF 檔案在所有主流瀏覽器（Chrome、Firefox、Safari、Edge）中正確顯示正體中文，無亂碼
- **SC-003**: 系統在使用者輸入變更後 500 毫秒內完成 localStorage 儲存，確保資料不遺失
- **SC-004**: 90% 的使用者在首次使用時，無需查看說明文件即可成功完成報價單建立與匯出
- **SC-005**: 系統在手機裝置（螢幕寬度 375px）與桌面裝置（螢幕寬度 1920px）上皆能正常操作，所有按鈕與輸入欄位可輕鬆點擊
- **SC-006**: 匯出功能在 95% 的情況下成功完成，失敗時保留資料並顯示明確錯誤訊息
- **SC-007**: 使用者可在報價單中新增至少 20 個項目，系統效能不受影響（無 UI 凍結或延遲）
- **SC-008**: 所有使用者導向的錯誤訊息使用正體中文，且提供明確的操作指引
